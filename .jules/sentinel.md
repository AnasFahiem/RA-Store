## 2024-06-27 - [Broken Access Control in Admin Header and Hero Server Actions]
**Vulnerability:** Several admin-facing Next.js server actions (`addHeroSlide`, `deleteHeroSlide`, `updateHeroSlideOrder`, `addHeaderSlide`, `deleteHeaderSlide`, `updateHeaderSettings`) utilized the `createAdminClient()` service role client which bypasses Row Level Security (RLS) but failed to enforce explicit role-based authorization checks (`getSession()` + role validation) before executing state-changing database operations. This allowed any unauthenticated or unauthorized user to manipulate hero and header components.
**Learning:** Next.js Server Actions are public API endpoints by default. Even if they are intended for use only within an admin dashboard UI, relying solely on RLS or UI-level routing guards is insufficient if the action uses a service role client. The application must enforce explicit authentication and authorization directly within the server action body.
**Prevention:** Always explicitly invoke `getSession()` and perform a role check (`session?.role === 'admin'`) at the very beginning of any server action that utilizes a privileged `createAdminClient()` or modifies sensitive data, before processing input or executing database queries.

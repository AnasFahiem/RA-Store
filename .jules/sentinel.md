## 2024-06-23 - Missing Role Authorization on Server Actions

**Vulnerability:** Found multiple server actions (`addHeroSlide`, `deleteHeroSlide`, `updateHeroSlideOrder` in `lib/actions/hero.ts` and `addHeaderSlide`, `deleteHeaderSlide`, `updateHeaderSettings` in `lib/actions/header.ts`) that bypass RLS because they use `createAdminClient()`, yet lacked application-level role-based authorization checks (e.g., verifying if the user has an `admin` or `owner` role). This allowed any user (even unauthenticated, if the API was publicly callable) to invoke these actions and arbitrarily add/delete hero and header slides.
**Learning:** Next.js Server Actions are public API endpoints. If a server action uses a service-role Supabase client (`createAdminClient()`), which bypasses database Row Level Security (RLS), explicit role-based authorization must be enforced directly inside the function. Relying solely on UI-level hiding of buttons does not secure the underlying endpoint.
**Prevention:** Always verify the user's authentication state and authorization role (`session?.role === 'admin' || session?.role === 'owner'`) inside *every* server action that performs privileged operations or uses `createAdminClient()`. Ensure consistent use of `getSession()` or `verifySession()` at the top of these functions.

## 2024-05-18 - JWT Secret Forgery Vulnerability
**Vulnerability:** The application was vulnerable to JWT forgery because it failed to explicitly validate the presence of the `JWT_SECRET` environment variable before initializing the JWT signing key using `new TextEncoder().encode(process.env.JWT_SECRET)`. In Node.js (v22+), passing `undefined` to `TextEncoder().encode()` results in a zero-length array. This creates a predictable signing key (an empty byte array), allowing an attacker to forge JWTs and escalate privileges (e.g., impersonating an admin) if the application starts without a valid `JWT_SECRET`.
**Learning:** Implicit type coercions and changes in standard library behaviors across different runtime versions (like Node v22+ evaluating `undefined` differently than older versions in `TextEncoder`) can lead to critical security regressions. Security-critical initialization must strictly enforce fail-closed policies rather than relying on assumed fallback behaviors.
**Prevention:** Always explicitly validate the presence and length of required environment variables for cryptographic operations before using them. Implement fail-closed error handling to prevent the application from starting in a vulnerable state.

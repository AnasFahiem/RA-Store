## 2024-05-30 - Fix price manipulation vulnerability in bundle creation
**Vulnerability:** A standard user could submit a manipulated payload containing custom values for `priceOverride` and `type` during bundle creation in the `createBundle` server action. Since the server action relied solely on input schema validation without performing explicit role checks on these privileged fields, an attacker could create a bundle with an arbitrarily low price and an administrative type.
**Learning:** Input validation schemas (like Zod) only validate data types, not authorization constraints. When server actions accept input for mixed-role operations, privileged fields must be explicitly filtered or overridden based on the user's role.
**Prevention:** Always enforce role-based access control directly within the business logic of server actions. For payloads containing fields restricted to certain roles, explicitly verify the user's authorization and securely override or discard those fields if the user is unprivileged, rather than trusting the validated schema data blindly.

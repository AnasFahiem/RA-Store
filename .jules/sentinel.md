## 2024-07-27 - Predictable JWT Secret Key Generation Vulnerability
**Vulnerability:** The application passed `process.env.JWT_SECRET` directly to `TextEncoder().encode()` without validating its presence. If the `JWT_SECRET` environment variable was missing or incorrectly configured, Node.js (v22+) would evaluate `undefined` to a zero-length array (or older versions coerce it to the predictable 9-byte string 'undefined'). This effectively hardcodes a predictable secret for JWT signing and verification, allowing an attacker to trivially forge arbitrary JWT tokens, bypass authentication, and escalate privileges.
**Learning:** Next.js and typical backend frameworks do not automatically fail the startup process or module initialization if a specific environment variable is missing unless explicitly checked. Security-critical cryptographic inputs must always be strictly validated before usage to fail closed (securely) rather than defaulting to an unsafe, predictable state.
**Prevention:** Always validate that required environment variables are present and meet length/complexity requirements before passing them into cryptographic functions. Use strict checks (e.g., `if (!process.env.SECRET) throw new Error(...)`) at module initialization time, or use schema validation (like Zod) for environment configurations.

## 2026-06-12 - Fix Broken Access Control in Hero and Header Server Actions
**Vulnerability:** The server actions for managing hero slides (`addHeroSlide`, `deleteHeroSlide`, `updateHeroSlideOrder` in `lib/actions/hero.ts`) and header components (`addHeaderSlide`, `deleteHeaderSlide`, `updateHeaderSettings` in `lib/actions/header.ts`) lacked authentication and authorization checks. Because these actions utilized `createAdminClient()`, which bypasses Row Level Security (RLS), any unauthenticated or unauthorized user could invoke these public API endpoints to arbitrarily modify or delete the store's hero slides and header components.
**Learning:** Next.js Server Actions are exposed as public API endpoints. When a Server Action uses a service-role client (like `createAdminClient()`) to bypass RLS, explicit role-based authorization checks must be implemented within the action itself to ensure only privileged users can execute the operation. Relying on RLS is insufficient when the service role is used.
**Prevention:** Always implement explicit authentication and authorization checks (e.g., using `getSession()`) at the beginning of any Server Action that mutates data, especially those using `createAdminClient()`, to ensure the requesting user possesses the necessary privileges (`admin` or `owner`).

## 2024-07-20 - Enforce JWT Secret Validation on Initialization
**Vulnerability:** The application failed to explicitly validate the presence of the `JWT_SECRET` environment variable before passing it to `TextEncoder().encode()`. In newer versions of Node.js (v22+), an undefined value evaluates to a zero-length array, resulting in an empty key. In older versions, it coerced to a predictable 'undefined' string. Both scenarios lead to critical key forgery vulnerabilities where attackers can forge valid JWTs and gain unauthorized access, including bypassing authentication and authorization mechanisms.
**Learning:** Next.js uses an environment variable system that doesn't inherently throw errors if a variable is missing at runtime. We shouldn't rely on implicit type coercion or downstream library errors when handling critical security materials like cryptographic keys.
**Prevention:** Always implement explicit validation and fail-closed policies for critical environment variables (like secrets and keys) immediately upon initialization or module load. Throw a clear, descriptive error if the required configuration is missing, preventing the application from starting in an insecure state.

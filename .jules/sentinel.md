## 2024-05-24 - Parameter Tampering in Bundle Creation
**Vulnerability:** The `createBundle` server action allowed any user, regardless of role, to provide a `priceOverride` and set the bundle `type` to `admin_fixed`. This could lead to a parameter tampering vulnerability where regular users might bypass product pricing by creating bundles with arbitrary prices.
**Learning:** Input validation schemas (like Zod) only validate data types and shapes; they do not enforce role-based authorization or prevent privileged fields from being submitted by unprivileged users. When using service-role Supabase clients (`createAdminClient`) that bypass RLS, explicit role checks must be manually enforced on sensitive fields within the action body.
**Prevention:** Always explicitly filter or override privileged fields based on the user's role after schema validation but before processing or persisting the data. When dealing with mixed-role actions, assign `undefined` to discard unauthorized fields like `priceOverride`.

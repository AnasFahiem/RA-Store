## 2025-02-26 - Parameter Tampering in Bundle Creation
**Vulnerability:** The `createBundle` server action accepted user-provided input fields (`type` and `priceOverride`) without validating the user's authorization to set those specific fields. This allowed any logged-in user to send a request defining a bundle as `admin_fixed` or applying an arbitrary `priceOverride`, which effectively acts as a parameter tampering and privilege escalation vulnerability.
**Learning:** Input validation schemas (like Zod) only validate data types and shapes; they do not enforce authorization or business logic constraints. Mixed-role server actions that accept the same payload structure for both users and admins must explicitly filter out privileged fields based on the requester's actual role.
**Prevention:** Always verify a user's role (`session?.role === 'admin'` or `'owner'`) before applying privileged fields from a user-provided payload. If the user lacks the necessary role, explicitly discard or override those fields with safe default values (e.g., `type = 'user_custom'` and `priceOverride = undefined`).
